# 3 分钟演示脚本

> 全程离线，不调用真实模型、不连接外部平台。使用“手动结构化事件模式”与预置演示库。

## 0. 准备（一次性）

```bash
cd recruitflow
python -m scripts.init_demo --reset   # 离线演示初始化（人工标注事件，通过 Harness 重放）
python -m streamlit run app.py
```

打开页面后顶部应显示“**人工标注事件演示**”。

## 1. 看台账与待确认（约 30 秒）

- 顶部「处理模式」保持“手动结构化事件模式”（不调用大模型）。
- 切到「招聘台账」：应看到 6 名候选人、7 条应聘记录；筛选项可试“姓名=李明”。
- 切到「待确认」：应为空（演示数据里的歧义已被确认解决）。

## 2. 新增一条应聘（约 30 秒）

- 切到「消息处理」，默认事件 JSON 是“新增候选人 C101 周晓 产品运营”。
- 点「处理」→ 显示“✅ 成功”，台账多一条记录。

## 3. 改期与重复（约 30 秒）

- 在「消息处理」里把事件 JSON 改为 reschedule（改期），点「处理」。
- 再点一次「处理」用同一消息 ID → 显示“🔁 重复投递”，台账不新增。

## 4. 歧义确认（约 30 秒）

- 注入一条 schedule_interview 且 `candidate_name="李明"`（不带 candidate_id）→ 点「处理」显示“⏳ 待确认”。
- 切到「待确认」→ 选择目标应聘记录 → 点「确认」→ 待确认列表清空、台账更新。

## 5. 看板（约 30 秒）

- 切到「招聘看板」→ 查看候选人数、应聘记录数、待同步任务数、当前阶段分布、待进行面试、超期跟进。
- 可勾选“使用固定统计基准时间”验证统计基准时间切换。

## 6. 同步失败与恢复（约 30 秒）

- 切到「同步管理」→ 勾选“模拟下一次同步临时失败”→ 点「执行到期任务」→ 看到任务进入“等待重试”。
- 取消勾选 → 再点「执行到期任务」→ 任务变为“模拟同步成功”。
- 点「查看模拟外部表格内容」确认外部记录与台账一致。

## 预期要点

- 顶部始终标注“企微消息入口为模拟；腾讯文档未接入”。
- 同步成功始终写作“模拟同步成功”，不声称腾讯文档已接通。
